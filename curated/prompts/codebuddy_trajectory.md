# CodeBuddy / 豆包经验投放规则（样例，尚未安装）

CodeBuddy 和豆包的会话记录都只存在服务端，本地没有可扫描的转录。这条规则让 agent 在任务收尾时把**可复用的结论**写成脱敏轨迹落到本机投放目录，由每 30 分钟的自动沉淀扫描接管判断与写库。客户端自己始终只读，不调用写入接口。轨迹格式与客户端无关。

安装方式（先不要做，等样例跑通后再决定）：CodeBuddy 追加到项目的 `CODEBUDDY.md`，或追加到 `~/.codebuddy/CODEBUDDY.md` 作为全局规则；豆包放进「技能 / 自定义指令」，并把投放目录写成 `~/.doubao/curated-inbox/`。

## 什么时候写

任务满足以下任一条件时，在收尾前写一份轨迹：

- 有可复用的解决方案，且能说清「下次什么情况可以直接用」；
- 故障排查：现象 + 判别依据 + 根因 + 修复方式；
- 踩坑：试了什么、为什么失败、后续如何规避；
- 配置/版本约束、方案取舍、可复现的 SOP。

以下情况**不写**，也不要为了凑数写半截：

- 一次性操作（临时参数、临时路径、只对本次成立）；
- 没有验证证据的推测；
- 纯问答、纯闲聊；
- 用户明确要求在本次会话中不要沉淀。

## 写到哪里

```
~/.codebuddy/curated-inbox/<日期>-<短标题>.jsonl    # CodeBuddy
~/.doubao/curated-inbox/<日期>-<短标题>.jsonl       # 豆包
```

- 一行一个 JSON 对象，UTF-8，不要包成数组，不要加注释；
- 同一会话续写同一个文件（追加），不要重写已有行；
- 单文件控制在 100 行以内。

## 行格式

| `kind` | 必填字段 | 说明 |
|---|---|---|
| `meta` | `session_id`, `workspace` | 首行；`session_id` 用本次会话标识，`workspace` 写项目绝对路径 |
| `user` | `text` | 任务目标，压缩成一句话，保留关键约束 |
| `assistant` | `text` | 关键判断、结论、取舍理由 |
| `tool` | `name`, `status` | `status` 只取 `ok` 或 `error`；工具名即可，不要贴输入输出 |
| `verification` | `text` | 怎么验证的、验证结果；没验证就不要写这一行 |

完整样例见 [`../examples/inbox_trajectory.jsonl`](../examples/inbox_trajectory.jsonl)。

## 红线

1. 不写代码、命令正文、完整日志。扫描时会剔除代码块，但文件本身是明文留在磁盘上的。
2. 不写密钥、token、密码、私有 URL、内网地址。不确定是不是敏感信息时按敏感处理，直接不写。
3. 不编造 `verification`：没跑通的验证就写成 `tool` 的 `error`，让判断环节看到真实证据。
4. 不写与本任务无关的内容；不复制整段对话。
5. 投放目录只放轨迹文件，不要放别的产物。

## 与其他链路的关系

本规则只负责落文件。脱敏、门禁、去重、幂等、游标与写库全部由 `curated.auto.cli` 完成。不要在 CodeBuddy 会话里调用 `record_experience` 写接口，也不要改 `~/.qoder/curated/` 下的状态文件。
