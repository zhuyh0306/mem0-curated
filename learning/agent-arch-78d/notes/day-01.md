## 精读笔记（3 条，能复述才算）

1. **uv 把「解释器版本」和「项目依赖」分开管**
   - 为什么重要：`uv python pin` 只锁解释器版本（写 `.python-version`），`uv lock` / `uv sync` 才管依赖；两者混在一起就会出现在错误的 Python 上装依赖。
   - 在本项目落在：仓库根目录的 `pyproject.toml` 与后续 `.python-version`。

2. **`uv lock` 与 `uv sync` 是两步，不是一步**
   - 为什么重要：`lock` 只解析并更新 `uv.lock`，不装；`sync` 才按 lock 落地到 `.venv`。CI 用 `uv sync --frozen`，lock 有改动直接失败，避免「本地能跑、CI 跑出新版本」。
   - 在本项目落在：依赖变更的提交流程（改 `pyproject.toml` → `uv lock` → 提交 lock 文件）。

3. **成本基线要按「单次 / 千次 / 月」三档算，且大头在上下文**
   - 为什么重要：只算一次问答看不出量级；把 system、工具描述、上下文、输出分开列，才知道优化该动哪一块。
   - 在本项目落在：后续 `curated/` 的检索与记忆注入都属于「上下文」这一项。
