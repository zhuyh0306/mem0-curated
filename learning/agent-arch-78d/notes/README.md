# 笔记规范

一个学习日记一个文件：`day-01.md` … `day-78.md`。没学的天不建空文件。

原文的要求只有一条：**精读要边读边写 3 条笔记，读完必须能复述**；扫读不写笔记，只记一句「这个东西在我项目里归哪个模块」。下面的模板是把它落成可复用的结构。

## 模板

```markdown
# Day N｜<标题>

日期：YYYY-MM-DD
用时：实际 / 计划（min）
今日验收物：<原文 📦 那一条>

## 精读笔记（3 条，能复述才算）

1. **<概念>**：<一句话定义>
   - 为什么重要：
   - 在本项目落在：
2. ...
3. ...

## 扫读：模块归属

| 资料 | 归属模块 | 一句话判断依据 |
|------|---------|---------------|
|      |         |               |

## 产出

- 文件/命令（可复现的最小验证）：
- 演示结果：

## 三行收尾

- 卡点：
- 绕过：
- 下次：

## 验收

- [ ] 3 条笔记能不看资料复述
- [ ] 能一句话说清项目落点
- [ ] 今日验收物真实存在且可复现
- [ ] 未完成项已登记为「已知限制」并写明补做日
```

## 写法要求

- **一条笔记只讲一件事**，标题用名词短语，不用「学习了…」这种句式。
- 每条笔记至少写一句「在本项目落在哪个文件/模块」，否则等于抄概念。
- 命令和代码只贴**能复现的最小片段**，不贴整段文档示例。
- 「卡点」写现象与根因，「绕过」写实际采用的替代方案，「下次」写可执行的判断规则（例如「先看 lock 文件再怀疑网络」）。
- 笔记里不放任何密钥、token、内网地址；需要引用就写「见 `curated/.env` 的某项」。
