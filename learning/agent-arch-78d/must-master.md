# 必须掌握清单

按周提炼，只保留「学完必须能自己讲出来、或必须能亲手做出来」的内容。原文的每日细节见 [plan.md](plan.md)。

标记约定：

- **复述**：合上资料能用自己的话讲清楚，讲不清就是没学会。
- **操作**：能不看教程在仓库里做出来，并能当场演示结果。
- **识别**：知道它存在、解决什么问题、什么时候该用，不要求默写。

## 贯穿全程的 10 条硬规则

1. 没有基线数字的优化都是猜测（第 1 周起）。
2. 每个交付物必须能在仓库里找到、能复现；做不完登记为「已知限制」。
3. 契约先行：先定入参/出参/失败码，再接模型。
4. 提示词是接口，不是文案；改版必须有对照测试。
5. 成本大头是上下文，不是输出；优化先动上下文。
6. 分层的目的不是好看，是让故障域可隔离。
7. 能用纯代码或固定 workflow 解决的，不要上 Agent。
8. 不能回归的模块等于没有验收。
9. 删不干净等于没删（DB、向量库、缓存三处都要过）。
10. 卡住 15 分钟就换实现或查资料，不硬耗。

## 第 1 周 · 工程基线（M0-1 基线冻结）

**定位**：把环境、仓库、技术栈、成本四条基线冻结，后面 12 周不再返工。

**必须掌握**

- **操作** uv 管 Python 版本与依赖：`uv python pin 3.11`、`uv add` / `uv add --dev`、`uv lock` 与 `uv sync` 的区别、`uv sync --frozen`（CI 严格模式）、`uv tree` 排查冲突、`uv audit`、`uv export --format requirements-txt`。
- **操作** Node 侧用 pnpm 管包与 workspace，不混用 npm/yarn。
- **操作** 写 `docker-compose.yml` 一次拉起全部依赖服务，并用一条 completion 证明「网关通 + trace 通」。
- **复述** ADR 记的是「为什么」，代码只记「是什么」；每篇 ADR 至少包含背景、选项、决策、后果。
- **复述** 选型矩阵五个维度：成本 / 运维 / 生态 / **退出成本** / 团队熟悉度；退出成本优先于性能峰值。
- **复述** 单次问答成本 = system + 工具描述 + 上下文 + 输出；三档测算（单次 / 千次 / 月）。
- **复述** 三种实现形态的判定顺序：纯代码 → workflow → autonomous agent，先证明「不用 Agent 会怎样」。

**验收**：`docker-compose.yml` + `env_check.sh` 全项通过；成本三档表有数字；3 篇 ADR 落地。

**自测**

1. 换一台机器，怎么在 30 分钟内复现这套环境？
2. 如果明年要换向量库，代价是什么？
3. 把单次成本降一半，你先动哪一块？

## 第 2 周 · 认知与架构设计（架构蓝图评审通过）

**定位**：建立四层职责与多租户边界的共同语言，让后面的模块有地方可放。

**必须掌握**

- **复述** 提示工程五层（PE/CE/HE/LE/GE）。原文只给缩写，学习时给每一层各写一句「管什么 / 失效时什么症状」，再和下面的四层架构对齐。
- **操作** TaskContract：入参、出参、约束、失败码四段齐全；同一份契约在 Python 与 TS 两侧实现，并有一致性 fixture 兜底。
- **复述** 四层职责：Gateway（唯一知道密钥的一层）/ Runtime（编排与恢复）/ Harness（循环、工具调用、终止条件）/ 治理层（权限、审计、评测）。
- **复述** 控制面与数据面的分界，以及 4 个人工审核点放在哪里。
- **复述** 多租户隔离三级：独立库 / 独立 schema / 行级策略（RLS）；`tenant_id` 要贯穿 请求 → DB → 向量库 → 日志 → 记忆。
- **识别** 零信任的三个组件：Policy Engine / Policy Administrator / Policy Enforcement Point。

**验收**：`architecture.md` 含职责边界表；多租户文档 + 5 条越权用例；风险登记册 v1。

**自测**

1. 哪一层挂了系统还能用？哪一层挂了必须停服？
2. 向量库里怎么保证 A 租户的数据不进 B？
3. 这套设计里，哪个决策最不可逆？

## 第 4 周 · 检索工程 RAG（R1 检索模块达标）

**定位**：把检索从「调一个接口」升级成可评测、可治理的模块。

**必须掌握**

- **复述** 三种切分策略（定长 / 语义 / 结构感知）的取舍；切分决定检索上限，后面调不回来。
- **操作** 数据入 Qdrant，并对比三种切分的召回差异。
- **操作** 混合检索：关键词（BM25）+ 向量，带 tenant 与时间过滤。
- **操作** cross-encoder 重排 top20 → top5，并用相似度阈值实现低相关拒答。
- **复述** Recall@k、MRR、nDCG 分别在衡量什么；为什么「答错」要先区分是检索问题还是生成问题。
- **复述** 知识条目要有版本号与失效日期，可见性过滤要测越权。

**验收**：ingest 脚本 + 切分对比报告；retriever + 10 条对比；rerank 阈值实验；30 条检索评测集与 Recall@5 / MRR 基线；检索回归用例进 CI。

**自测**

1. 一张大宽表怎么切？
2. 查一个具体单号，你会用向量检索吗？
3. 旧口径的文档怎么防止被召回？

## 第 5 周 · 运行时与编排（M1 分布式运行时骨架）

**必须掌握**

- **操作** 手写 `while` 循环 harness，跑通 3 类任务。
- **操作** 用图编排把「规划 → 检索 → 分析 → 校验 → 输出」拆成节点，每个节点有单测。
- **操作** 反思节点：校验失败触发重规划，上限 2 次并记录重规划日志。

**验收**：`mini_harness.py` 跑通 3 类任务；图 + 节点单测；恢复测试记录；崩溃接管演示；M1 验收报告 + 复现脚本。

## 第 6 周 · 上下文治理（上下文治理验收）

**定位**：把上下文当预算来管，而不是把能塞的都塞进去。

**必须掌握**

- **操作** context builder 按优先级装配五层，并统计每层 token 占比。
- **操作** compaction：超过阈值就摘要，但必须保留证据；对比压缩前后的答案质量。
- **复述** 证据链要求：每条结论都能回指到表 + 查询 + 行号或段落。
- **操作** 预算守卫：超限时按优先级裁剪并留下日志。
- **操作** OTel + Langfuse 跑通一次全链路 trace，并用回放定位一次答案偏差。

**验收**：`context_builder.py` + 装配顺序文档；compaction 前后对比表；证据 schema；budget guard 超限测试；完整 trace 与回放结论。

3. 用户质疑一条结论，你能在多长时间内拿出依据？

## 第 7 周 · 工具与协议治理（工具治理验收）

**定位**：工具是给模型用的接口，要像 API 一样设计、校验和授权。

**必须掌握**

- **操作** 重构 5 个工具：合并重复能力、改掉歧义命名、裁剪返回字段；用同一套评测对比成功率。
- **操作** tool registry：每个工具有 schema 校验、幂等约定、超时。
- **复述** Skill 是一个完整能力包（含配套 fixture），不是一段提示词。
- **操作** 写最小 MCP server（2 个工具），并在真实客户端完成接入调用。
- **复述** 凭据代理：模型只见工具名，不见密钥；每次调用留审计。
- **识别** 工具红队：围绕「过度代理」（Excessive Agency）设计 10 条工具攻击用例并执行，结果落进 `tool_redteam.jsonl` 与结果表。

**验收**：工具重构前后成功率对比；registry + 校验测试；Skill 包 + fixture；MCP 接入记录；credential broker + 审计样例；`tool_redteam.jsonl` 结果表。

**自测**

1. 工具返回 2 万 token 的原始数据，是谁的问题？
2. 模型能不能自己决定调用「删除」类工具？靠什么拦？
3. 同一个工具被重试两次，怎么保证不重复扣款/重复写？

## 第 9 周 · 记忆治理（记忆治理验收）

**定位**：记忆能写、能取、能忘、不串租户，而且可评测。这一周和本仓库 `curated/` 的目标几乎重合，可以直接对照实现。

**必须掌握**

- **复述** 四层记忆：短期（会话）/ 长期（跨会话）/ 语义（事实）/ 情景（事件）；每层写清判断规则。
- **操作** 记忆 schema 四类字段：租户 / 用户 / 时效 / 置信度。
- **复述** 写入判据：显式指令 vs 高价值事实；记忆污染从写入那一刻开始。
- **操作** 抽取器：模型抽取 → 结构化 → 去重入库，测 20 条准确率。
- **操作** 加权检索 `recency + relevance + confidence`；新旧说法冲突时要有消解规则。
- **操作** 删除某用户全部记忆：DB + 向量库 + 缓存三处都要清，并有残留检查脚本。
- **操作** per-tenant namespace，跑跨租户召回测试。

**验收**：`memory_schema.json`；writer + 20 条准确率；retriever + 15 条召回；forget 流程 + 残留检查；mem0 隔离配置 + 测试结果；记忆治理验收报告（隔离 / 遗忘 / 冲突 / 成本四维）。

**自测**

1. 记忆中记错了，比不记更糟吗？怎么防止把闲聊记成事实？
2. 新旧两条记忆矛盾时信谁？规则写在哪？
3. 记忆规模涨 10 倍，会先崩哪一环？

## 第 13 周 · 受控进化与发布（M3 生产就绪）
